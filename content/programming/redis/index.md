这是一套**边写边学的教材**，不是命令手册。

规则只有一条：**课上不给你现成的项目，每一课的代码由你自己敲进自己的工程里**。我负责讲清「为什么这么设计、这一步该写成什么样、怎么验证它真的对」，你负责把它跑起来。

---

## 最终你会建成什么

一个叫 `redis-practice` 的 Spring Boot 服务（后面再补 Go 版对照），它包含三个业务域：

```text
redis-practice/
├── shortlink/     短链：生成、跳转、访问计数、热门榜
├── voucher/       优惠券秒杀：库存、一人一单、异步下单
├── social/        社交：关注、Feed、签到、UV
└── common/        Redis 配置、key 规范、缓存工具、分布式锁
```

它不是一个玩具：秒杀要扛并发、缓存要防穿透击穿、锁要能容错、消息要能重投。
每一课往这个工程里加一块，加完这块必须能独立验证。

## 怎么学

**节奏**：每课 2–4 小时，至少 60% 时间在敲代码和看输出。一课的检查点全过再进下一课。

**三条纪律**

1. **每条结论都要有证据**：命令输出、耗时、内存增量、`CLIENT LIST` 的连接数。
   没有证据的「感觉快了」不算结论。
2. **先跑通，再破坏**：功能对了之后，一定再做一次并发、超时、重启或错配置。
   Redis 的知识点几乎都是在「坏了」的时候才真正理解。
3. **不许跳过验证命令**：每一课的检查点都是为了让你亲眼看到 Redis 里的数据长什么样。

**卡住了怎么办**

- 先看第 0 课写的 `/health`：连不上、认证失败、超时，三者报错完全不同
- 再看 `SLOWLOG GET` 和 `MONITOR`：前者回答「为什么慢」，后者回答「到底发了什么命令」

## 环境准备

| 需要 | 说明 |
| --- | --- |
| JDK 17 + Maven | 本机已有，`mvn -v` 能看到版本即可 |
| 一个 Redis 7.x | **用你自己的服务器**，不需要本地 Docker |
| `redis-cli` | 服务器上有；本机装一个更方便对照 |
| `curl` + Python | 验证接口和格式化 JSON |
| 编辑器 | IntelliJ IDEA 或 VS Code 均可 |

服务器侧建议确认这几项（第 0 课会带你逐项看）：

```conf
bind 0.0.0.0            # 或只绑内网 IP，别裸奔公网
protected-mode yes
requirepass <你的密码>
maxmemory 512mb         # 实验环境给个上限，避免打爆服务器
maxmemory-policy allkeys-lru
```

- 实验数据实验专用：`FLUSHDB` 允许，但只在你确认过的那台实例上
- 每课结束在对应笔记里补一段「我实际踩到的坑」，比抄我的坑有用十倍
